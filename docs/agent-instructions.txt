EXACT CONTRACT — all keys are required; no extra keys at any level

Return one UTF-8 JSON object, without Markdown fences, commentary, credentials, account numbers, raw tool responses, purported signatures or verification fields. Maximum input is 1,000,000 UTF-8 bytes for the CLI. Every label is nonempty and contains no control characters. Unknown keys, duplicate JSON keys and duplicate observation dates are invalid. All quantities below are strings unless stated otherwise.

- schema_version: exactly "n170.agent-handoff.v1".
- synthetic: boolean, true for explicitly synthetic demonstrations; false only for supplied actual observations. This does not prove authenticity.
- source: object with exactly broker (1–80 characters), connector (1–80), tools (array of 0–40 unique actually called tool-name strings, each 1–80), retrieved_at (ISO timestamp with timezone (YYYY-MM-DDTHH:MM:SS, optional 1–3 fractional second digits, then Z or numeric ±HH:MM offset no larger than ±14:00), or null if no retrieval occurred). Do not invent tool calls or retrieval time. No calls means tools:[] and retrieved_at:null. For an unavailable source use clear labels such as "Unavailable". Time is a sender clock claim, not independent evidence.
- account_scope: owner-approved public alias, 1–160 characters; never an account number. Do not guess this or the requested dates. Ask first if the owner has not specified them.
- currency: one of "USD", "EUR", "GBP", "CHF", "CAD", "AUD", "JPY". No implicit currency conversion; ask if the requested currency is unknown.
- frequency: JSON number, one of 252 (daily trading), 365 (daily calendar), 52 (weekly), 12 (monthly), 4 (quarterly), 1 (yearly). Preserve the actual observation schedule; frequency does not override date checks.
- requested_period: object with exactly start and end, real calendar dates "YYYY-MM-DD"; start on or before end. Use the owner's requested dates.
- coverage: object with exactly pagination ("complete", "incomplete" or "unknown"), missing_periods (array of 0–100 objects containing exactly start, end, reason; dates as above with start on or before end, reason 1–300 characters), unsupported_events (array of 0–100 descriptions, each 1–300 characters). Include unresolved live/paper, scope, currency or valuation-time questions here; never silently choose a financial treatment.
- flow_timing: "interval_end", "intraperiod" or "unknown". It applies to every gross external flow, including offsetting flows. No gross activity review means timing is unknown.
- observations: array of 0–500 objects, each containing exactly date, nav, external_flow, source_ref. date is a real "YYYY-MM-DD" valuation date; dates must strictly ascend. nav and external_flow are explicit plain decimal strings (maximum 50 characters, magnitude <=1000000000000000, at most 18 fractional places); JSON numbers, null, exponents, separators and missing amounts are rejected. Opening external_flow must be "0" to be calculable. Positive later flows are deposits; negative later flows are withdrawals. source_ref is a private field path/navigation aid of 1–240 characters with no credentials/account number. It proves neither a tool call nor authenticity. Do not invent a zero flow or round a value to satisfy limits.
- mapping: object with exactly date, nav, external_flow, each a source field-path description of 1–120 characters. Explain valuation date meaning. If no retrieval occurred use "unavailable"; do not invent source fields.

Readiness requires at least two actual supported observations, matching requested start/end, a reported completed retrieval with at least one called tool, complete pagination, no missing periods or unsupported events, and supported interval-end flow timing. No data: observations:[]. One observation may be included if it actually exists, but remains blocked. Missing evidence always stays visible. Return unknown/incomplete states; never claim completeness to pass the parser. Total loss, unsafe numerical values or unsupported flow treatment remain blocked. Short or sparse series may have a withheld annualized volatility while the supported return evidence is still reviewable.
